# 实施计划

## 项目基线

本计划把 [Dev.md](../Dev.md) 与 [v1.1 追加契约](FRONTEND_APPEND_V1_1.md) 的开发任务拆分为八个受 CI 门禁约束的阶段。当前状态为 **阶段四下载与断点续传进行中：真实认证、WebDAV 文件列表、Room 下载队列、前台传输和文件打开已接线，仍待设备兼容验证与写操作实现**。静态页面和 Demo 数据仍不代表真实业务已经全部完成。

已确定的工程决策：

- Android 包名：`com.resdownload.android`。
- 最低支持 Android 8.1（API 27）。
- 先实现 Mock 后端与 Repository 替身，稳定 UI 状态、导航和领域接口后，再接入真实认证、WebDAV 与更新服务。
- GitHub Actions 对所有事件执行 Release lint、单元测试和无签名打包；仅在 `main` 上通过受保护的 `release` Environment 注入正式签名并构建 Release APK。
- 真实后端路由采用 `{code,message,data}` envelope；GitHub 与 QQ 的角色均以后端返回为准，邮箱验证码登录已移除。
- Android 直连 WebDAV，当前已完成凭据 DTO、内存缓存、路径安全、PROPFIND 解析、Range 校验和三并发下载队列；凭据密码不落盘。
- 本地 Android 构建默认 `DEMO_MODE=true`；CI 通过 Gradle 属性注入真实 API 地址并设置 `demoMode=false`。
- GitHub Actions 同时执行 Android Release 门禁和 backend Go test/vet/build。

## CI 门禁与实施顺序

每个阶段都按“接口与模型 -> Mock/测试 -> UI 或基础设施 -> 真实集成 -> 异常路径”的顺序提交。面向 `main` 的 Pull Request 必须由远程 **Android CI** 执行以下命令并通过后才能合并：

```text
./gradlew --no-daemon lintRelease testReleaseUnitTest assembleRelease
```

推送到 `main` 或在 `main` 手动触发的 CI 成功后，还应确认 `android-real-release-apk` artifact 可下载。该 artifact 通过 Actions Variable `API_BASE_URL` 注入真实 HTTPS 后端，以 `demoMode=false` 构建，并使用受保护 `release` Environment 中的发布密钥签名。Pull Request 不读取签名 Secrets，但仍执行无签名打包；涉及设备行为的阶段仍需记录模拟器或实体设备验证结果。

## 阶段一：项目初始化（已完成）

**目标**

建立包名为 `com.resdownload.android` 的单应用 Android 工程，接入 Kotlin、Compose、Material 3、依赖注入、导航、日志与主题基础能力，并以 Mock 数据呈现最小可导航界面。

**交付物**

- Gradle Wrapper、`app` 模块和基础构建配置。
- `core`、`data`、`domain`、`feature`、`di` 的初始职责边界。
- 登录、文件列表、下载、设置、个人中心等页面的导航占位与 Mock UI 状态。
- 浅色、深色和跟随系统的主题框架；统一 Loading、Empty、Error 等页面状态模型。
- 可由 Android CI 生成的 Release APK。

**验证**

- CI 的 Release lint、单元测试和 APK 构建全部通过。
- 冷启动、页面导航、预测性返回栈、Mock 状态切换与明暗主题无崩溃。
- 在 API 27 环境完成一次启动与主要页面冒烟检查。

**主要风险**

- 工程依赖或插件组合不兼容，导致 CI 无法解析或编译。
- Mock 模型与后续真实接口耦合过深，增加替换成本。
- 把占位交互误认为已完成认证、WebDAV 或下载能力。

## 阶段二：登录模块与 v1.1 基础设施（已完成）

**目标**

完成 GitHub OAuth（PKCE、后端换取 token）与 QQ OpenSDK 手机客户端授权流程，建立安全的会话持久化、角色识别和退出登录能力。

**交付物**

- Android `User` 已迁移到 nullable `name/email` 与 `LoginType`。
- 后端 DTO/Retrofit API 契约、统一 envelope 解码和加密会话存储基础。
- GitHub 服务端 HTTPS callback、App PKCE 一次性登录票据、QQ provider token 后端校验和服务端角色判定。
- WebDAV 凭据生命周期、Basic Auth、PROPFIND/HEAD/GET/PUT/MKCOL/DELETE/MOVE 协议核心。
- 已完成 Custom Tabs OAuth 回调、真实认证状态驱动的根导航、文件 ViewModel、Room 下载/上传任务、前台服务传输和 SAF 文件及文件夹选择；仍待完成应用内更新安装。

**验证**

- 单元测试覆盖 QQ wire contract、用户映射、token 刷新和退出清理。
- Mock 流程先通过，再使用非生产测试后端和已登记签名的真机 APK 验证 GitHub、QQ 两种登录方式与授权回调。
- 客户端日志、崩溃信息和持久化明文中不出现 token、验证码或 client secret。

**主要风险**

- GitHub 回调配置不一致或 PKCE 状态校验失败；QQ AppID、包名或 APK 签名与开放平台登记不一致。
- 仅依赖客户端角色判断造成越权；最终授权必须由服务端执行。
- 凭据刷新并发、失效状态和安全存储兼容性处理不完整。

## 阶段三：文件列表模块（进行中）

**目标**

在只读路径上接入 WebDAV 目录浏览，完成层级导航、刷新、文件详情、受限内存预览及完整页面状态。

**交付物**

- WebDAV 客户端抽象与 `PROPFIND` 响应解析。
- 文件/目录领域模型、Repository、路径规范化与错误映射。
- 文件列表、面包屑或当前路径、返回上级、下拉刷新、空态和错误重试。
- 文件详情/下载面板，以及按 MIME/扩展名显示的文本、图片和可安全解析文档预览。

**验证**

- 解析测试覆盖命名空间、特殊字符、空目录、缺失属性和异常响应。
- 使用 Mock WebDAV 固定数据验证导航和状态，再对目标测试服务执行只读联调。
- 普通用户与管理员均只能看到本阶段允许的操作入口。
- 覆盖 Range 被忽略、超限响应、ZIP 解压预算、XML 复杂度、文本编码和不支持格式隐藏。

**主要风险**

- 不同 WebDAV 服务对 `PROPFIND`、路径编码、时间和 ETag 的实现存在差异。
- 路径拼接或解码不严格可能造成目录越界。
- 大目录加载与 Compose 列表状态恢复可能影响性能和体验。
- 远程文件属于不可信输入，预览必须保持字节、解压、解析和渲染上限且不得落盘。

## 阶段四：下载与断点续传（已完成）

**目标**

实现可观察、可重试、可取消的文件下载任务，并在服务端支持时通过 Range、ETag 或 Last-Modified 安全续传。

**交付物**

- 下载任务模型、持久化状态和前台下载服务。
- NotificationChannel、进度通知、完成通知与文件打开流程。
- `.part` 临时文件、Range 请求、完整性判断、失败重试和取消清理。
- 下载任务页以及运行中、成功、失败和取消状态。
- 当前下载速度、`basename(n).ext` 重名规则，以及本地文件缺失时的完成任务清理。

**验证**

- 单元/集成测试覆盖 200 完整响应、206 部分响应、Range 不支持、ETag 变化和损坏临时文件。
- 在 API 27 与较新 Android 测试通知、前台服务、进程重启后的任务恢复和 FileProvider 打开文件。
- 使用大小不同的测试文件验证进度、字节数、重试与最终内容一致性。

**主要风险**

- 进程被系统终止、网络切换、存储空间不足或文件写入失败造成状态不一致。
- 服务端错误声明 Range 能力，导致拼接出损坏文件。
- 新版 Android 的通知权限与前台服务限制需要按系统版本分支处理。

## 阶段五：管理员功能（已完成）

**目标**

在服务端强制授权的前提下，为管理员提供上传、重命名、移动、复制和删除操作，普通用户保持只读。

**交付物**

- 管理员专属上传页、最多三文件并发的持久队列、实时进度和速度，以及新建文件夹、重命名、移动/复制目标目录选择和删除二次确认界面。
- 上传成功任务自动清除；失败与取消任务保留重试和手动删除操作。
- SAF 单文件及递归文件夹上传；目录父级优先创建，文件夹根目录、子目录和空目录结构保持不变。
- 管理员纯文本在线编辑、原编码写回和基于强 ETag 的 `If-Match` 冲突保护。
- WebDAV `PUT`、`DELETE`、`MOVE`、`COPY` 适配器。
- 文件名、路径穿越、重名冲突与目录删除提示的校验。
- 操作完成后的列表刷新、错误提示和可重试策略。

**验证**

- 权限测试确认普通用户既看不到入口，也无法通过直接请求完成写操作。
- 在隔离测试目录验证单文件/文件夹上传、三并发等待补位、重命名、移动、复制和删除的成功及失败路径。
- 覆盖特殊字符、重名、非法路径、网络中断和大文件上传。

**主要风险**

- 客户端 UI 权限被绕过；服务端或 WebDAV 凭据必须限制真实能力。
- 各 WebDAV 服务对 `MOVE`、覆盖和递归删除语义不一致。
- 管理员长期凭据进入客户端会造成严重泄露风险，应使用短期凭据或代理。

## 阶段六：公告与版本检查

**目标**

设置页从仓库根目录读取纯文本公告和版本配置，并使用完整版本名提供手动更新检查。

**交付物**

- 仓库根目录 `notice.txt` 与设置页公告入口。
- 公告加载、空态、错误重试、大小限制和纯文本安全渲染。
- 关于页面读取 `BuildConfig.VERSION_NAME`。
- 仓库根目录 `latest_version.txt`、三段数字版本比较、更新结果弹窗与浏览器下载跳转。

**验证**

- 覆盖公告内容、空文件、404、网络失败和重试。
- 验证公告不使用 WebView，不执行 HTML 或脚本，并限制最大响应体。
- 覆盖 `2.0.1`、`2.1.1`、多位数字版本段、相等版本、较新本地版本及非法配置。

**主要风险**

- Raw GitHub 不可用时需保留明确的空态或错误状态。
- 公告属于远程不可信文本，只能按纯文本渲染。
- 更新地址属于远程输入，只允许通过系统浏览器打开有效的 HTTPS URL。

## 阶段七：设置与深色模式

**目标**

完善设置、主题持久化、账户信息、关于与退出入口，并统一全应用的 Material 3 Expressive 视觉和错误反馈。

**交付物**

- 设置页直接展示账户信息和关于入口，不保留独立个人中心路由；账户区域显示 GitHub 或 QQ OAuth 头像与昵称，不展示邮箱，并支持默认回退。
- `SYSTEM`、`LIGHT`、`DARK` 三种主题模式及 DataStore 持久化。
- Android 12+ 莫奈自动取色开关，以及关闭后的预设、恢复默认、HCT 自定义主题色和八种官方英文名配色方案；旧版 Android 直接使用自定义主题色。
- 所有页面、弹窗、底部面板、Snackbar、状态栏与导航栏的深色适配。
- 可选的下载缓存清理，并提供明确范围与确认反馈。

**验证**

- 主题模式、自动取色和主题色切换立即生效且重启后保持，所有主要状态均检查浅色和深色表现。
- 自动取色关闭时验证 HCT 生成的关键前景/背景角色满足 Material 对比度要求。
- 用户资料、头像、角色与登录方式显示一致，头像加载失败回退默认图标，退出登录返回受限入口。
- QQ 互联 SDK 只在持久化政策版本确认用户同意后初始化；QQ provider token 不写入应用持久化存储，头像只接受受信任的腾讯 HTTPS 主机。
- 缓存清理不会删除进行中的任务或用户选择保留的文件。

**主要风险**

- 主题状态在 Activity 重建或导航切换时闪烁、丢失。
- 动态颜色和固定语义色的对比度不足。
- 缓存边界定义不清可能误删下载结果。

## 阶段八：兼容、测试与发版准备

**目标**

完成 Android 8.1 起的兼容适配、全流程回归、安全检查和发布前质量收敛；发布签名由受控的 Release CI 注入。

**交付物**

- API 27 及代表性较新系统的兼容性测试记录。
- 登录、文件浏览、下载续传、管理员操作、更新和主题的端到端回归结果。
- 通知、存储、前台服务、安装权限、TLS 与统一错误处理的版本差异适配。
- 已知问题、发布阻断项与回滚条件；发布配置在单独受控流程中管理。

**验证**

- Android CI 持续通过，签名 Release APK artifact 可安装并完成冒烟测试。
- 按 Dev.md 验收标准执行功能、权限、异常与兼容性矩阵。
- 检查依赖、日志、网络配置、敏感信息存储和 APK 来源完整性。

**主要风险**

- API 27 与最新目标平台之间的行为差异集中暴露在存储、通知和前台服务。
- 测试服务与生产 WebDAV 能力不一致，导致协议兼容问题遗漏。
- 发布密钥泄露或丢失将阻断可信更新；必须隔离保管、限制访问并建立备份和轮换预案。

## 阶段完成规则

一个阶段只有同时满足以下条件才可标记完成：范围内交付物进入主分支；远程 CI 通过并产出签名 Release APK；对应自动化测试通过；设备相关验证有结果；未解决风险有明确负责人和后续阶段。当前状态以各阶段标题和本文开头的项目基线为准。
